3. Таблиця вартості та припущення free tier

USD/місяць, 730 годин, on-demand; AWS us-east-1, GCP us-central1; без податків і promotional/trial credits. Порівнюється core власного проєкту. Фактичний AWS database - RDS PostgreSQL db.t4g.micro, Single-AZ, 20 GB gp2 (не Aurora з прикладу).

Припущення навантаження:
- 1 API-запит/с під час активних годин, 200 мс billed duration, 512 MiB RAM; Lambda ARM64, Cloud Run 1 vCPU, без перекриття запитів. Deployed Cloud Run concurrency limit = 10; у розрахунку одночасних запитів = 1.
- Відповідь 2 KiB до Європи; GCP egress 0.12/GiB. North America-only безкоштовну outbound quota не застосовано.
- AWS RDS працює всі 730 годин у кожному профілі. GCP показано для двох режимів Cloud SQL; storage, backups та idle public IPv4 залишаються платними після зупинки.
- Невеликий frontend: AWS S3 storage 0.003 GB, 10,000 GET/місяць; трафік Firebase статики нижчий за 360 MB кожного дня.
- Reports/LLM workloads і cold-start overhead виключено. Це прогноз окремого core кожної хмари; під час паралельного утримання обох розгортань обидва рахунки складаються. Навантажувальний тест не запускався.

Free tier вважається доступним і не витраченим іншими workloads:
- Lambda: 1 млн запитів і 400,000 GB-с/місяць; CloudFront: 1 TB transfer і 10 млн запитів/місяць.
- Cloud Run request-based: 2 млн запитів, 180,000 vCPU-с і 360,000 GiB-с/місяць.
- Firebase Hosting: 10 GB storage, 360 MB/day transfer; Artifact Registry: 0.5 GiB; Secret Manager: 6 active versions / 10,000 accesses; Cloud Logging: 50 GiB/project/month.

За цих припущень GCP дешевший у перших трьох профілях, AWS - у busy. У тихих профілях домінує RDS/Cloud SQL або retained IPv4; у busy GCP вирішальною стає CPU-складова Cloud Run. Пастка GCP: SQL не паузиться на idle, а зупинка не прибирає storage/backups та idle IP; min instances або instance-based billing також збільшують рахунок.
